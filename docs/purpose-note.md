# 目的と代表操作

新規事業の企画 Project の工程0で、事業の地図を「柱→工程→成果物→項目」の枝として描き、工程定義の下書きを作るための材料にする。作業役が地図をもとに工程定義の JSON を作り、既存の検査を通して人が承認する。Editor は定義の自動確定や承認を行わない。

## 利用者

### UR-01 企画リーダー・早川
事業の柱を枝に分け、順番や親子関係を変えながら、必要な仕事の全体像を整理する。

### UR-02 アナリスト・石田
枝に仮説、数字の出所、担当を記し、企画の根拠と未解決の点を追えるようにする。

### UR-03 DX開発・中川
地図の階層と枝の情報を読み、作業役が工程定義の JSON を作る元として使う。定義の検査と承認は別の工程で行う。

## 代表操作

各操作の拒否時は内容と編集履歴を変えず、理由を利用者に示す。

### OP-01 枝を加える・名前を変える
利用者：UR-01、UR-02。柱の下に工程を足し、枝の名前を変更する。存在しない親への追加や、定められた入力上限を超える変更は拒否する。

### OP-02 並べ替える・親を変える
利用者：UR-01。兄弟の順番を入れ替え、枝を別の親へ子孫ごと移す。根の移動、自分自身や自分の子孫の下への移動は拒否し、循環を作らない。

### OP-03 枝を畳む
利用者：UR-01、UR-02、UR-03。子孫を一時的に隠して全体を見渡し、再び開く。存在しない枝への操作や、子のない枝を畳む操作は拒否する。読み取り専用では表示だけを一時的に切り替え、保存内容は変えない。

### OP-04 色・印と枝の情報を付ける
利用者：UR-02、UR-01。色や印で論点を見分け、枝のメモに仮説・数字の出所（URL か資料名の文字）・担当の3つを記す。存在しない枝や、定められた値・入力上限に合わない変更は拒否する。数字の正しさや出所の信頼性の判定は利用者が行う。

### OP-05 削除とUndo
利用者：UR-01、UR-02。不要な枝を子孫ごと削除し、誤った編集はUndoで戻す。根の削除や、戻せる編集がないときのUndoは拒否する。

### OP-06 外からの提案を検討する
利用者：UR-01、UR-02。外部の作業役が出した案を枝ごとの差分で見て、必要な枝を採り、不要な枝を採らない。採用した変更はUndoで戻せる。古い元データに基づく提案、存在しない対象への変更、権限のない変更、木の条件に反する変更は採用を拒否する。提案の確認だけでは内容を変えない。

### OP-07 読み取り専用で開く
利用者：UR-03、UR-01、UR-02。地図と枝の情報を読み、工程定義の材料や確認に使う。読み取り専用では追加・変更・削除・移動・提案の採用やUndoなど内容を変える操作を、画面と外部操作の両方で拒否する。

### OP-08 保存して再び開く
利用者：UR-01、UR-02、UR-03。編集した地図を保存し、後で階層・順序・枝の情報を読み直す。不正な構造や対応しない形式の読み込みは拒否し、現在の地図を部分的に上書きしない。保存に失敗した場合は失敗を知らせ、未保存の変更を保つ。

## 新しい Editor が要る理由

表は項目の値を比較するには適するが、考えを枝として広げながら親子関係と兄弟の順序を一緒に組み替える操作には向かない。表の表示を木に切り替えるだけでは、まだ工程定義の項目になっていない仮説も含めて枝を追加し、畳み、枝単位で提案を採否する編集経路が得られない。

グラフは任意の点と線の関係を表せるが、根が一つの順序付きの木、親が一つで循環しない条件、枝の子孫をまとめた移動や折りたたみを前提にしていない。自由配置の図を描くだけでは、事業の地図の構造を保ちながら工程定義の材料として扱いにくい。そのため木を編集の中心にする専用 Editor が必要である。

## 扱わないこと

### EX-01 自由配置や任意の交差リンク
座標を手で保存して図形を自由に配置することや、親子関係以外の枝同士を矢印で結ぶことは扱わない。配置は木の構造をもとにする。

### EX-02 複数人の同時編集
複数人が同じ地図を同時に編集し、変更を統合する機能は扱わない。

### EX-03 画像・添付ファイル
枝への画像の貼り付けやファイルの添付は扱わない。出所は枝の情報として記す。

### EX-04 工程定義の確定とAIの実行
Editor が工程定義を直接確定・承認すること、AIを呼び出すことは扱わない。外部の作業役が提案や定義の下書きを作り、人が判断する。

### EX-05 初版で扱わない連携
テンプレートや部品の再利用、他形式への変換・取り込み、他の成果物を地図から直接編集することは扱わない。
