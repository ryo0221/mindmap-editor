# 判断の案

作業役が、仕様に無いことで決めたこと・答えてもらったことの案。受け入れるときに見て、仕様に取り込むか決める。

## マインドマップ形式の具体化

設計案の上限（ノード2000、根を深さ0として最大16、子200、本文200・メモ4000 Unicodeコードポイント、リンク各128、canonical UTF-8 512 KiB）を採用する案。ノードIDは n- と128ビットの小文字16進32桁、文書IDは同じ乱数の d- 形式。枝の仮説・出所・担当は構造化せずメモに記す。形式情報は artifactKind と schemaVersion に置き、JSONの未知フィールドは拒否する。
