- 理由：ゲート5つが通り、石田が開発 Host で代表操作（名前・子を足す・読み取り専用）を確かめた。左の枝が欄の端で切れる点は検証の工程で直す。

## 判断

### 枝のIDの発行

新しい枝のIDは作成側が128ビットの乱数から決め、コマンドの適用時に既存IDとの重複を拒否する。Redoは元のIDを復元する。

### 操作提案の基準確認

操作提案には基準文書の短い指紋を渡し、準備後の適用時は準備時の文書と完全一致することも確認する。Host側の提案の基準版確認を併用する。

### 枝のIDの発行元

枝を作る画面または操作提案が暗号学的乱数からIDを決め、コマンドの適用時に既存IDとの重複を拒否する。やり直しでは同じコマンドのIDを使用する。

### 枝 ID の発行主体

形式仕様の「Host が発行」は、枝を作る画面または操作提案の作成側が乱数で ID を決め、コマンドの適用時に重複を拒否するものと読み替える。画面では crypto.getRandomValues による 128 bit の値を使い、Redo は同じコマンドの ID を再利用する。

### 地図の表示範囲

枝の座標からキャンバスの範囲を計算し、地図欄内でスクロールできるようにする。枝の追加時は選択された新しい枝を表示範囲に入れる。

### 未確定入力の保護

枝の情報に未確定の入力がある間は、枝を追加する前に適用または取消を促し、入力が失われないようにする。
